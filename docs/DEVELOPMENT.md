# Speaker Stage 개발 참고

사용법과 배포 요약은 [README](../README.md)를 참고하세요.

### 실시간 동기화

- 상태·포커스·표정·중앙 제어에는 변경 순서를 기록합니다. 같은 변경의 중복 수신이나 이전 변경의 지연 수신으로 최신 상태를 되돌리지 않습니다. 초기 스냅샷에도 적용한 변경 번호를 함께 전달하고, 그 응답이 만들어진 뒤의 변경은 다시 적용합니다. 담당 GM이 접속 준비 중에 놓친 자신의 변경은 같은 번호로 재전송합니다.
- 액터의 등장마다 별도 식별자를 사용합니다. 퇴거한 등장을 기록하므로 오래된 목록이 캐릭터를 되살리지 않으며, 나중에 다시 올린 캐릭터를 이전 퇴거·표정·대사 패킷이 건드리지 않습니다. 새 등장에는 이전 대화·타이머도 넘기지 않습니다.
- 같은 액터를 여러 사용자가 동시에 올리는 경우에만 GM을 우선하고, 같은 구분이면 Foundry 사용자 목록 순으로 하나의 등장을 선택합니다. 서로 다른 액터의 동시 등장도 위치·사용자·액터 순으로 정렬하여 모든 화면의 배치를 일치시킵니다. 일반적인 등장·퇴거의 소유권 기준은 그대로입니다.
- GM의 명시적인 스피커 선택과 실제 발화가 공유 포커스를 바꿉니다. 화면 갱신이나 다른 GM의 로컬 드롭다운 값이 공유 포커스를 덮지 않으며, 표정·목록 갱신이 마지막 발화 진영을 되돌리지 않습니다. 백스테이지의 붉은 선택 하이라이트는 자신의 스피커 셀렉터 선택을 계속 표시합니다.
- 표정 갱신은 액터를 올린 사람의 목록 갱신과 별도로 전파합니다. GM이 PL 등장 캐릭터의 표정을 바꿔도 함께 반영되며, 올린 사용자와 GM/PL 진영은 바뀌지 않습니다. 액터 문서의 이미지·스탠딩 변경을 반영할 때는 현재 스테이지의 감정을 유지합니다.
- 등장 송신보다 채팅 생성이 먼저 도착한 경우, 송신자가 이미 올려 둔 등장임을 표시한 직접 입력 대사만 최대 5초간 기다렸다가 출력합니다. 귓속말·주사위·시스템 카드와 임의 소켓의 채팅 주장은 이 대기열에 들어가지 않습니다.
- 초기 동기화 응답이 없으면 2~15초 간격으로 재요청합니다. 복구용 GM이 아직 동기화되지 않았거나 응답하지 않으면 다른 활성 GM을 확인하며, 복구할 GM이 없으면 보유한 상태를 유지합니다. Foundry 사용자 접속 훅 외에 소켓 재연결 시에도 다시 동기화합니다.
- 중앙 제어 변경은 첫 활성 GM이 최종 처리합니다. 복구 도중의 조작·미확인 요청과 변경 순서도 보존합니다. 중앙 제어를 끈 상태에서는 복구 스냅샷이 각 사용자의 개인 스테이지 표시 여부를 변경하지 않습니다.

이 정보는 실행 중 메모리에 유지하며 기존 월드 설정 키를 변경하지 않습니다. 코드 교체 후에는 GM과 PL 모두 새로고침하여 같은 통신 형식을 사용해야 합니다. 모든 클라이언트를 종료한 뒤의 스테이지 복원이나 과거 대화 내역의 재생을 위한 영구 저장 기능은 아닙니다.


## 파일 구성과 검증

`scripts/lichsoma-speaker-stage.js`는 초기화·공유 상태·기능 연결을 담당합니다. 각 기능은 같은 `SpeakerStage` 상태를 사용하며, 기존 정적 메서드 호출 방식과 설정 키를 유지합니다. 기능 파일의 메서드에서 `this`는 `SpeakerStage`입니다. 같은 이름의 메서드를 중복 연결하면 초기화 시 오류를 내도록 하여 덮어쓰기를 방지합니다.

| 파일 (`scripts/` 기준) | 담당 기능 |
| --- | --- |
| `lichsoma-stage-settings.js` | 설정 등록, 웹폰트 해석·적용, 글자 크기 |
| `lichsoma-stage-backstage.js` | 백스테이지, 플레이어 버튼, 스피커 등록·선택 연동 |
| `lichsoma-stage-socket.js` | 메시지 검증, 다중 GM 담당자·상태 동기화 |
| `lichsoma-stage-sync.js` | 변경 순서·재시도·복구 대기열·등장 식별·충돌 정렬 |
| `lichsoma-stage-overlay.js` | 기본 스테이지 표시·퇴장, 이미지 우클릭 퇴거 |
| `lichsoma-stage-standing.js` | 스탠딩 데이터, 모든 이미지의 공통 진영 배치·활성 스피커·대화창 |
| `lichsoma-stage-portraits.js` | 감정 이미지 선택·교체·페이드 |
| `lichsoma-stage-chat.js` / `lichsoma-stage-dialogue.js` | 채팅 입력 감지·대사 타이핑 / 표시용 HTML·공유 서식 처리 |
| `lichsoma-stage-integrations.js` | 사이드바 크기 감지, 외부 HUD 연동 |
| `lichsoma-stage-standing-manager.js` / `lichsoma-stage-webfont-editor.js` | 스탠딩·웹폰트 전용 설정창 |
| `lichsoma-stage-background.js` / `lichsoma-stage-background-settings.js` | 배경 표시·전환 / 배경 슬롯 설정창 |

설정창은 공유 컨트롤러를 전달받아 생성하므로 진입 파일을 다시 import하는 순환 의존성이 없습니다. 기능 파일은 진입 파일의 import로 로드하며, `module.json`에 중복 등록하지 않습니다.

스타일은 공통 변수, 백스테이지, 오버레이, 대화 서식, 스탠딩 관리, 스탠딩 배치, 외부 HUD 연동으로 분리했습니다. 기존 배경·웹폰트 편집 스타일과 함께 `module.json`의 순서로 로드하고, 테마 팔레트는 마지막의 `lichsoma-stage-theme.css`에서 적용합니다.

모듈 폴더에서 타이머·소켓 회귀 검사를 실행할 수 있습니다.

```text
node --test tests/dialogue-timers.test.cjs tests/socket-state.test.cjs
```

작업 공간의 `review-speaker-theme` 검사는 개발용 보조 자료이며 이 모듈 폴더에 포함되지 않습니다. 자동 검사는 Foundry 객체 일부를 대체하므로 실제 FVTT 다중 클라이언트 실행 확인을 대신하지 않습니다.

## GM 담당자와 권한 검증

GM이 여러 명이면 Foundry의 `game.users.activeGM`이 지정한 첫 번째 활성 GM이 전체 상태 동기화와 중앙 제어의 최종 처리를 담당합니다. 담당 GM이 접속을 종료하면 다음 활성 GM이 맡습니다. 다른 GM도 액터를 올리고 내릴 수 있으며, 중앙 제어 변경은 담당 GM에게 요청해 모든 클라이언트에 같은 상태를 반영합니다. 일반 액터 갱신은 각 사용자가 올린 액터만 교체하므로 다른 GM·플레이어의 액터를 덮어쓰지 않습니다.

첫 GM이 재접속하거나 담당자가 바뀌면 다른 활성 GM이 있는 경우 그 GM에게 기존 상태를 복구한 뒤 동기화 요청에 응답합니다. 플레이어와 추가 GM은 접속 시 현재 담당 GM에게 상태를 요청하며, 응답은 대상 사용자·요청 번호·담당 GM이 일치할 때만 적용됩니다. 플레이어가 액터를 올리는 갱신은 할당 캐릭터 또는 소유 권한이 있는 액터로 제한합니다.

소켓 검증은 전달된 `userId`와 Foundry 사용자 문서를 대조하는 클라이언트 검증입니다. 표준 모듈 소켓에 별도의 서버 발신자 인증을 추가하는 방식은 아닙니다.
